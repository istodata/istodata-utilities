# Elementor 4.4 policy assessment — 2026-11-11

This is a risk-based policy proposal, not a claim that all 4.4 combinations have passed testing.

- Core 4.4.0 and Pro 4.4.0 staging files were checked against official and licensed vendor archives. The relevant Core interaction JavaScript and 24 PHP interaction files match the 4.3.6 baseline; Pro interaction JavaScript differs only in its version banner. The existing interaction workaround also checks its required JavaScript capabilities and falls back when unavailable. These limited source findings support allowing the 4.4 stable patch series for Atomic Interactions under policy, not labeling it individually tested.
- Pro 4.4 adds Atomic Loop avoid-duplicate and offset handling; Core changes Atomic style and asset-related code. Actual staging editor insertion and native Save Draft succeeded. An untouched Loop saved without query settings; a modified Loop stored typed avoid-duplicates and offset settings. The first editor-only observations did not establish opt-in serialization or same-request cache side effects; these were checked separately below.
- On the separate dev application 6779430, actual default Atomic opt-in Save Draft produced a typed loop query and cache opt-in. With the native Elementor Element Cache disabled by a test-request-only option filter, a real frontend request with Atomic Loop and Classic Posts produced identical native/cold/hit HTML, ordered 22 asset URLs and 19 inline hashes; cold stored both and hit bypassed both original renders, preserving the observed Pro avoid list. Enabled Atomic avoid duplicates or offset bypassed Atomic caching while the Classic element remained a hit. Limits: only one published source post; no multi-item avoidance/ordering proof, WPML (not installed), device matrix, full browser matrix, or separately fetched asset contents. The older metrica attempt did not complete.
- Stable patch ranges cannot predict future semantic vendor changes. The read-only monitor must check relevant official diffs and issues, and a confirmed regression needs a feature-specific known-bad declaration and corrective Kit release. Existing privacy and cache safeguards remain unchanged.
