# Proposed update to the existing Elementor compatibility monitor

Update the prompt of the existing `elementor-atomic-interactions` heartbeat, keeping its name, schedule, target chat, state and notification settings. Do not create another monitor. Replace its old per-patch release requirement, update-blocking claim and per-version notification rule with the following:

> Read the release-owned compatibility registry and current guards. Once daily, check official stable Elementor and Pro release notes, targeted diffs of the vendor files/APIs actually used by Kit, and actionable upstream issues including Elementor #35831. Changelog silence is not proof of compatibility. A declared bounded patch range permits runtime use under policy; it does not mean each pair has been tested. Preserve the distinction between installed and available versions, exact accepted pairs, policy-allowed pairs, known-bad exclusions, and individually tested evidence.
>
> Notify only when a change needs action: a relevant behavior/API change, a credible issue or known incompatibility, a supported-range boundary, a missing reliable source, or a change to a previously reported finding. Explain affected Kit features, evidence and uncertainty, exact versions and official links. Recommend focused investigation or testing only where relevant; do not require a staging/editor matrix or Kit release for an ordinary in-range patch with no relevant change found. Never claim that Kit blocks native WordPress updates: unsupported affected Kit features are bypassed while settings remain intact. Unknown and known-bad combinations remain subject to the registry and its feature-specific guards.
>
> When evidence suggests risk to rendering, side effects or privacy, ask the existing implementation chat to investigate; propose a precise feature-specific exclusion and corrective release if confirmed. Retain previous accepted combinations except for a documented, explicitly decided exception. Check the implementation chat before assigning work; report evidence and limits, never infer release approval, and do not install, modify files or settings, purge, commit, publish or create automations from the scheduled run. The coordinator reviews any proposed release separately.

The existing prompt says Kit blocks updates and requires a new declaration/release and notification for every unlisted patch. Those statements conflict with the current native update policy and the 2026-11-10 user decision. This file is a proposal only; the running automation has not been changed.
