# Maintained tests and staging tools

Run commands from the plugin repository root.

## Local regression checks

```sh
php tests/elementor-compatibility.php
php tests/elementor-update-guard.php
node tests/elementor-compatibility-drift.cjs
php tests/atomic-interaction-breakpoints.php
node tests/atomic-interaction-breakpoints.cjs
php tests/elementor-device-visibility.php
php tests/elementor-fragment-bootstrap.php
php tests/elementor-fragment-context.php
php tests/elementor-fragment-graph.php
php tests/elementor-fragment-assets.php
php tests/elementor-fragment-diagnostics.php
php tests/elementor-fragment-poll.php
php tests/elementor-fragment-replay-order.php
php tests/simple-repeater-required.php
php tests/simple-repeater-wpml.php
```

Atomic browser tests require explicitly provisioned vendor fixtures; see
`ATOMIC-INTERACTIONS.md`. Licensed fixtures remain ignored and excluded from ZIPs.

Per-element opt-in declares shared output across pages and users. Third-party
versions and unknown hooks are not blanket prerequisites. The graph/context
tests exercise supported structures and concrete private/replay exclusions.
`elementor-fragment-excerpt.php` and `elementor-fragment-purge.php` require a
real authorized WordPress staging environment, not standalone PHP.
`fragment-cache-optin-search.py` is an origin staging check.

## Current staging acceptance tools

`fragment-cache-generic-*` covers generic registered widget roots: four WP Menu
widgets, two Template/loop dropdowns, a core Text Editor and a custom widget with
native frontend settings and separate CSS/JS. It checks real render/construction
bypass, GR/EN cross-page/user output and subsequent query/excerpt parity, mobile
menu fixtures, native preview, concrete privacy exclusions, cold-request locking,
protected purge and a real menu-item API edit with exact test-title cleanup.
Fixtures and credentials are staging-only and excluded from the package. Native
English empty menu output is valid; shared current-page classes can remain frozen.

`fragment-cache-optin-*` and `fragment-cache-en-compare.cjs` cover the current
administrator opt-in policy, concrete privacy controls, handler-synchronized
menu behavior, native preview/diagnostics and concurrency/purge. Earlier blanket
hook/source policy helpers are archived under
`docs/archive/2026-10-02-fragment-policy/`.


`fragment-cache-access-*`, `fragment-cache-preview-*` and
`fragment-cache-build-verify.php` belong to the final Kit acceptance workflow.
They require explicitly authorized staging access, temporary private sessions
where applicable, and cleanup. They are not ordinary offline regression tests.
Keep `fragment-cache-staging-check.py` and `fragment-cache-assets-check.py`:
current acceptance scripts import their parser/asset helpers.

Evidence is in root `docs/fragment-cache-access-staging.md` and the access,
preview and wording JSON/screenshot files. Tests, docs and archives are not
distributed in the plugin ZIP. Generated bytecode, packaging scratch folders
and probe ZIPs are ignored.
